# MODX Count & Like — просмотры, лайки и дата публикации

Небольшое дополнение для **MODX Revolution 2.x**: на странице статьи выводит дату публикации, число просмотров и кнопку «Нравится». Не требует jQuery, Composer, cron или отдельного MODX-пакета. Это **ручная установка исходников**, а не transport package.

> **Происхождение:** за основу взята идея `PostViews`, разработанная в переписке 9 апреля 2026: задержка 5 секунд, 12-часовое окно повторных просмотров, прямое атомарное SQL-обновление вместо `resource->save()`. Здесь реализация переработана: для переносимости статистика находится в собственных таблицах, повторные просмотры ограничиваются **на сервере**. Лайки — **новая** функция; ранее обсуждавшийся рейтинг звёздами не переносится. `publishedon` — штатное поле MODX.
>
> **Статус:** проверен синтаксис PHP 8.4 и Node.js 22; интеграция с реальным MODX 2/MySQL на staging/production **не проверена**. Перед установкой на рабочий сайт протестируйте на копии.

## Что умеет

- Показывать **дату публикации** из `modResource.publishedon` (например, `06.11.2026`). Ничего дополнительно для даты в БД создавать не нужно.
- Показывать **просмотры**. После 5 секунд на видимой странице отправляется AJAX-запрос, который засчитывает **не больше одного просмотра одной статьи за 12 часов на браузер** (проверка на сервере).
- Ставить **и снимать лайк**: один активный лайк статьи на браузер. При клике счётчик меняется без перезагрузки.
- Показывать актуальные значения и состояние лайка на странице с MODX-кешем: динамические данные получает JSON-API с `Cache-Control: no-store`.
- Работать с любыми шаблонами MODX 2, в том числе при использовании Fenom/pdoTools.

**Ограничения:** идентификатор браузера хранится в `HttpOnly; SameSite=Lax` cookie (`mcl_vid`, срок 365 дней). Это не учёт уникальных людей: разные браузеры/очистка cookie считаются отдельными. От автоматических накруток на уровне ботнета эта реализация не защищает. Счётчик не является аналитикой вроде Яндекс Метрики. IP-адреса не сохраняются, но хеш cookie — псевдонимный идентификатор; учитывайте требования к уведомлению о cookie.

## Установка на MODX Revolution 2.x

### Шаг 1. Резервная копия и окружение

Сделайте **бэкап базы и файлов сайта**. Рекомендуется MODX **2.8.x**, PHP **7.4+** (рекомендуется поддерживаемая вашим MODX версия PHP), MariaDB/MySQL с InnoDB и доступ к базе через phpMyAdmin/Adminer. Дополнение пока не тестировалось на всех версиях PHP/MODX.

Проверьте префикс таблиц MODX в `core/config/config.inc.php`: обычно `modx_`, но бывает другой.

### Шаг 2. Создайте три таблицы

Откройте файл [`sql/install.sql`](sql/install.sql) и выполните SQL **в базе данных именно нужного сайта**. Если ваш префикс — не `modx_`, замените его **во всех трёх именах таблиц** перед выполнением:

- `{prefix}mcl_stats` — итоги просмотров и лайков по статье;
- `{prefix}mcl_viewers` — когда браузер последний раз просмотрел статью;
- `{prefix}mcl_likes` — активные лайки по статье и браузеру.

Существующие таблицы MODX `site_content` и TV этот SQL не изменяет. Повторный запуск `CREATE TABLE IF NOT EXISTS` не удалит данные.

### Шаг 3. Загрузите файлы в `assets`

Из GitHub скопируйте **три файла** из папки `assets/components/modx-count-like/` на хостинг, сохранив пути:

```text
/site-root/assets/components/modx-count-like/api.php
/site-root/assets/components/modx-count-like/engagement.js
/site-root/assets/components/modx-count-like/engagement.css
```

Здесь `/site-root/` означает **корень публичного сайта**, где лежит его `config.core.php`. Если в MODX путь к `assets` изменён, сохраните относительную структуру `components/modx-count-like/` внутри соответствующего `assets`, а путь к `config.core.php` поправьте в `api.php` (строка с `$root = dirname(__DIR__, 3)`). Сервер должен исполнять `api.php` как PHP, а не отдавать его текстом.

### Шаг 4. Создайте сниппет в Manager

В MODX Manager: **Элементы → Сниппеты → Создать сниппет**. Назовите его **`PostEngagement`**. Вставьте **весь код** из [`modx/snippets/PostEngagement.php`](modx/snippets/PostEngagement.php). Вставляйте **без** `<?php` и `?>` — файл специально подготовлен для редактора сниппетов MODX.

Сохраните сниппет. Он автоматически регистрирует JS и CSS (`regClientScript`/`regClientCSS`), поэтому при стандартном выводе страницы вручную подключать их не нужно.

> Для использования *статического* сниппета лучше хранить PHP за пределами публичной папки (например, в защищённом `core/`). Файл из папки `modx/snippets` репозитория **не нужно** выкладывать в публичный `/assets`.

### Шаг 5. Добавьте в шаблон полной статьи

В нужном месте шаблона MODX вставьте **некешируемый** вызов:

```modx
[[!PostEngagement]]
```

Данные будут показаны рядом, например: `06.11.2026  ◉ 120  ♥ 15`. Дата выводится только если `publishedon` заполнено. Просмотры и лайки сначала берутся из БД, затем уточняются через AJAX.

Если шаблон работает на Fenom, используйте вызов:

```smarty
{'PostEngagement' | snippet}
```

Для листингов/карточек статей **отключите учёт просмотров** (иначе открытие списка засчитает просмотр каждой карточки):

```modx
[[!PostEngagement? &id=`123` &trackViews=`0`]]
```

Вместо `123` подставьте ID карточки через ваш pdoResources/Fenom-шаблон. Учёт просмотров включайте на **полной странице** статьи.

### Шаг 6. Очистите кеш и проверьте

В Manager: **Управление → Очистить кеш** (или «Сайт → Очистить кеш», в зависимости от интерфейса). Затем:

1. Откройте **опубликованную** статью по HTTPS; её дата должна совпадать с `publishedon`.
2. В DevTools → Network проверьте ответ `api.php?id=ID` со статусом **200**, JSON с `ok: true`.
3. Через 5 секунд (пока вкладка видима) должен пройти `POST` с `action: "view"`; число просмотров увеличится на **1**.
4. Обновите страницу: ещё один просмотр **не** засчитывается в течение 12 часов. В другом браузере просмотры считаются отдельно.
5. Нажмите ♥: лайков должно стать на 1 больше. Нажмите ещё раз: лайк снимается. Обновите страницу: состояние должно сохраниться.
6. В базе выполните `SELECT * FROM modx_mcl_stats WHERE resource_id = ID;`, заменив имя таблицы/ID на свои.

Если на странице не появляются JS/CSS из-за нестандартного кеширования шаблона, добавьте эти подключения **один раз** непосредственно в HTML-шаблон (путь замените, если ваш `assets_url` другой):

```html
<link rel="stylesheet" href="/assets/components/modx-count-like/engagement.css">
<script src="/assets/components/modx-count-like/engagement.js" defer></script>
```

Не подключайте один и тот же JS дважды. Если используете статическое подключение, уберите из сниппета две строки `regClientCSS`/`regClientScript`.

## Параметры сниппета

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `&id` | текущий ресурс | ID другой статьи, например в карточке |
| `&showDate` | `1` | выводить `publishedon` |
| `&showViews` | `1` | выводить число просмотров |
| `&showLikes` | `1` | выводить кнопку лайка |
| `&trackViews` | `1` | учитывать просмотры (на листингах ставьте `0`) |

Пример без даты и без учёта просмотров:

```modx
[[!PostEngagement? &showDate=`0` &trackViews=`0`]]
```

## Перенос старых просмотров из `viewcount`

В исходном решении `PostViews` (апрель 2026) просмотры записывались в поле `viewcount` ресурса. **Новая версия не меняет его автоматически**, поэтому при миграции сначала перенесите исторические цифры. **Сначала сделайте бэкап.** Если исторические просмотры не нужны, этот раздел можно пропустить.

**Вариант А: `viewcount` — физическая колонка `modx_site_content`.** Убедитесь, что она есть:

```sql
SHOW COLUMNS FROM `modx_site_content` LIKE 'viewcount';
```

Если колонка существует, выполните:

```sql
INSERT INTO `modx_mcl_stats` (`resource_id`, `views`, `likes`)
SELECT `id`, GREATEST(CAST(`viewcount` AS UNSIGNED), 0), 0
FROM `modx_site_content`
WHERE `viewcount` REGEXP '^[0-9]+$'
ON DUPLICATE KEY UPDATE `views` = GREATEST(`views`, VALUES(`views`));
```

**Вариант Б: `viewcount` — TV с именем `viewcount`.** Проверка:

```sql
SELECT id, name FROM `modx_site_tmplvars` WHERE name = 'viewcount';
```

Если TV есть и хранит числовые значения, запрос для переноса:

```sql
INSERT INTO `modx_mcl_stats` (`resource_id`, `views`, `likes`)
SELECT v.`contentid`, CAST(v.`value` AS UNSIGNED), 0
FROM `modx_site_tmplvar_contentvalues` AS v
JOIN `modx_site_tmplvars` AS t ON t.`id` = v.`tmplvarid`
WHERE t.`name` = 'viewcount' AND v.`value` REGEXP '^[0-9]+$'
ON DUPLICATE KEY UPDATE `views` = GREATEST(`views`, VALUES(`views`));
```

**Важно:** эти примеры подходят только при указанных схемах хранения. Если `viewcount` — поле стороннего компонента с собственной таблицей, сначала выясните фактическое место хранения, затем скорректируйте SELECT. Все SQL-примеры предполагают префикс `modx_`. Запускать миграцию лучше **до** подключения нового учёта, не изменяя историческое поле.

## Устройство и безопасность

- AJAX-API проверяет существование опубликованного ресурса; `POST` принимает только запрос с **того же origin** (проверка `Origin`/`Referer` и `Sec-Fetch-Site`). Не открывайте CORS для этого эндпоинта.
- Оба действия (`view`, `toggle_like`) выполняются внутри транзакции InnoDB с блокировкой строки статистики; суммы обновляются атомарно. Нет `modResource->save()`, лишней очистки MODX-кеша и гонки простого «прочитал + 1 → сохранил».
- Сервер хранит SHA-256 случайного cookie-токена, а не IP; `localStorage` дополнительно снижает число запросов, **но не является защитой** (серверное окно 12 часов — основное).
- Если понадобится защита от массовых ботов, настройте rate-limit в веб-сервере/CDN для `/assets/components/modx-count-like/api.php` и антибот-защиту. Не считайте эту схему точной статистикой уникальных пользователей.
- Таблица `mcl_viewers` со временем растёт. Старые записи **можно** удалять, итоговый счётчик сохранится:

```sql
DELETE FROM `modx_mcl_viewers`
WHERE `last_viewed_at` < UTC_TIMESTAMP() - INTERVAL 30 DAY;
```

  Не очищайте `mcl_likes`, пока нужен учёт прежних лайков: иначе старые голоса пропадут из проверки, а итог в `mcl_stats` разойдётся с таблицей.
- При использовании собственного CMP/уведомления о cookie опишите технический cookie `mcl_vid` и хранение псевдонимных идентификаторов. Классификацию cookie и правовое основание определите с учётом требований вашего сайта.

## Диагностика HTTP 500 и даты 1970

Если API возвращает `{"ok":false,"error":"server_error","error_id":"..."}`, откройте **Manager → Управление → Журнал ошибок** (MODX Error Log) и найдите строку `[MODX Count & Like][error_id]`. Та же ошибка дублируется в **PHP error_log** хостинга. Публичный JSON специально не показывает текст SQL-исключения и пути на сервере.

Частые причины: не выполнен `sql/install.sql`, другой префикс таблиц, отсутствует одна из трёх таблиц, у пользователя БД нет прав записи, проблемы с InnoDB или недоступна БД. Проверьте в phpMyAdmin (замените префикс):

```sql
SHOW TABLES LIKE 'modx_mcl_%';
SELECT * FROM modx_mcl_stats WHERE resource_id = 81;
```

**Дата 01.01.1970** в ранней версии возникала из-за приведения строкового `publishedon` к `(int)`. Обновите код сниппета `PostEngagement` на текущий из репозитория, сохраните и очистите кеш MODX. Дата берётся из `publishedon`, а не из `createdon`.

**Обновление после раннего релиза:** замените `assets/components/modx-count-like/api.php` и обновите код сниппета `PostEngagement` из `modx/snippets/PostEngagement.php`. JS, CSS и структуру трёх таблиц менять не нужно. Затем очистите кеш. После обновления при повторном HTTP 500 скопируйте `error_id` и соответствующую строку журнала (без паролей и конфиденциальных данных).

## Если не работает

| Симптом | Проверить |
| --- | --- |
| `api.php` выдаёт `modx_config_missing` | `config.core.php` в ожидаемом корне; при нестандартной структуре исправьте `$root` |
| `api.php` выдаёт `server_error` | префикс SQL-таблиц, их права, MODX Error Log, наличие PDO MySQL |
| `403 origin_denied` | одинаковый домен/порт API и страницы; наличие `Origin` или `Referer`, reverse proxy и настройки Referrer-Policy |
| `404 resource_not_found` | ID ресурса, опубликован ли, не удалён ли, не действует ли ограничение `pub_date/unpub_date` |
| Не меняется число просмотров | подождать 5 секунд на **видимой** вкладке; проверить `localStorage` и серверные 12 часов |
| Значение на мгновение старое | при слабой сети число уточнится GET-запросом API; исключите кеширование JSON на CDN |
| Не отображается дата | `publishedon` пустое или равно 0 — заполните дату публикации в MODX |
| В шаблоне Fenom не исполняется | проверьте синтаксис вызова и обработку шаблона pdoTools |

## Локальная проверка исходников

```bash
bash tests/check.sh
```

Требуются `php` и `node`. Скрипт выполняет **только синтаксические** проверки, не заменяет установку на тестовом MODX с настоящей БД.

## Совместимость

Предназначено для **MODX Revolution 2.x**, обычных фронтенд-ресурсов контекста `web`, MySQL/MariaDB. Нет зависимости от SendIt, FormIt, pdoTools или jQuery. MODX 3 не поддерживается этим `api.php` без отдельной адаптации bootstrap. На много-контекстных или мультиисточниковых сайтах нужны дополнительные проверки контекста и маршрутизации.
